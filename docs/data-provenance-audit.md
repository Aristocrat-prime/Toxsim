# Data provenance audit

**Review date:** 2026-10-28  
**Inputs reviewed:** recovered archive's `poison_database.py`, `pubchem_cache.json`, `smiles_repairs.json`, and `fix_smiles.py`.

## Findings

### Compound count and scope

The archived quick-start describes ten curated entries. The local database also loads eight cache records, so the effective list can be larger than ten. The exact count should be generated by the app and qualified by source/status, rather than stated as a fixed number in a README.

### Fields that need evidence

The database contains fields such as molecular formula, SMILES, mechanism, target, organ sensitivity, half-life, volume of distribution, clearance, bioavailability, LD50, and toxicity threshold. These fields do not all have the same evidence requirements.

A PubChem compound record may support identity-related information, but it does not automatically substantiate a human pharmacokinetic parameter, an organ-sensitivity score, an interaction multiplier, or a predicted outcome. The archive's generic fallback values for some of these fields should not be treated as compound-specific facts.

### Repair mapping

The archive's repair map stores replacement SMILES strings, but the mapping does not preserve all of the information needed for a scientific audit, including the original string, the reason for the change, a stable source record/version, retrieval date, and reviewer decision.

The repair script queries a live external service and rewrites source text in place. This can make results change over time and makes it harder to reproduce exactly which structure was used in a given release. A safer maintenance workflow is to create a reviewable patch and preserve provenance, rather than mutating data during setup.

### Structure validation

A successful SMILES parse or a matching molecular formula is only a syntax/consistency check. It does not prove that a record's compound name, stereochemistry, salt form, source identifier, and molecular structure all refer to the same substance.

### Citation and redistribution

The source header refers generally to PubChem and curated literature, but each scientific field needs its own traceable source. Before redistribution, review the applicable database terms and any copyright, attribution, or other conditions for copied text, images, and derived data.

## Required record format

For each compound and each scientific parameter, track:

- Stable identifier and canonical display name.
- Original source URL or database record ID.
- Retrieval date and source/version.
- Field name, value, and unit.
- Evidence type: measured, literature-derived, estimated, synthetic, or unknown.
- Population/species, route, formulation, and experimental context where relevant.
- Transformations and any human review.
- Confidence/uncertainty and known limitations.
- Data licence/terms review status.

Unknown values should remain unknown. A software default must not be presented as an evidence-based value.

## Release gate

Do not describe this dataset as verified or validated until identity and parameter provenance have been reviewed field by field. Do not treat chemical structure validity as evidence of toxicological prediction accuracy.
